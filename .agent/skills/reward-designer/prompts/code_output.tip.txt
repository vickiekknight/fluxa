Some helpful tips for writing the reward function code:
    (1) Write each reward term as a separate function following the Isaac Lab RewTerm pattern.
    (2) Define a dictionary called 'reward_dict' containing RewTerm objects pointing to those functions.
    (3) Do not include imports. Use the standard Isaac Lab MDP naming conventions.
    (4) SceneEntityCfg's constructor is SceneEntityCfg(name: str, body_names: list). The first argument is `name`, NOT `asset_name`. Example: SceneEntityCfg("robot", body_names=["panda_hand"])
    (5) You may find it helpful to normalize rewards using torch.exp with a temperature parameter. Each transformed component should have its own temperature variable.
    (6) Reward terms for desired behavior should be positive. Do not negatively penalize lack of desired behavior.
    (7) SIGN CONVENTION — a reward function returns a POSITIVE magnitude and the `weight` carries the sign. For a penalty, return the positive magnitude of the undesirable quantity and give the term a NEGATIVE weight: `def joint_velocity(env, asset_cfg): return torch.sum(torch.square(env.scene[asset_cfg.name].data.joint_vel), dim=-1)` applied with `weight=-0.0001`. Isaac Lab's own reach reward does exactly this: position_command_error returns a positive distance and is applied with weight=-0.2. Returning a NEGATIVE value AND giving it a NEGATIVE weight makes the penalty a REWARD, and the policy will maximise the behaviour you meant to suppress.
    (8) When using the exponential function, make sure your input is bounded. Clamp if necessary.
    (9) Make sure any new tensor or variable is on the same device as the environment tensors.
    (10) Every RewTerm MUST set a weight: RewTerm(func=..., weight=<float>, params={...}). Omitting it fails config validation with "Missing values detected ... .weight".
    (11) RewTerm accepts only `func`, `weight` and `params`. Everything your function needs goes INSIDE params, e.g. params={"asset_cfg": SceneEntityCfg("robot", body_names=["panda_hand"]), "command_name": "ee_pose"}. There is no `scene_entities`, `asset_cfg` or `command_name` keyword on RewTerm itself.
    (12) Use only names the environment code already defines or that are already imported: torch, mdp, RewTerm, SceneEntityCfg, ManagerBasedRLEnv. Quaternion helpers such as quat_conjugate, quat_mul and quat_inverse are NOT available.
    (13) Every key in reward_dict must be a UNIQUE, descriptive name for that term (e.g. "reaching_position", "orientation_tracking", "action_smoothness"). Never reuse a key and never use the class name "RewTerm" as a key -- Python keeps only the last value for a repeated key, so the other terms are silently discarded.
    (14) Define `reward_dict` as a MODULE-LEVEL dictionary literal: `reward_dict = {"term_name": RewTerm(...), ...}` at the top level of the file, after your functions. Do NOT wrap the terms in a factory function that builds and returns a dict, and do not name any function `reward_dict`.
    (15) Each reward function must declare one named parameter per key in its params dict -- e.g. params={"asset_cfg": ..., "command_name": ...} requires `def my_reward(env, asset_cfg, command_name)`. Isaac Lab unpacks params as keyword arguments, so a function declared as `def my_reward(env, params)` fails with "expects mandatory parameters: ['params']".
